Three failure cases to remember

Lost storage confirmation

The sensor retries the same UUID; the relay avoids duplicates. This only works while the sensor still retains the alert.

Missed acknowledgement

welcome contains at most 100 recent alerts. An older control-room alarm can stay stale after reconnecting.

Disconnected sensor

The last reading can stay visible after disconnecting. A visible value does not prove the sensor is still measuring.

Supporting boundaries: identity and deployment

Browser session and role

Login sets an HttpOnly, SameSite=Strict session cookie; SQLite stores the token hash. hello checks the requested role. The control room requires the operator role. Logout closes that session’s sockets; heartbeat checks session expiry. Sessions default to 12 hours.

Sensor service identity

The sensor authenticates with a token in hello. A different sensor ID is refused while another is connected; the same ID replaces its old socket. Acknowledgement identity comes from the operator’s server-side session.

One relay, one database

Docker Compose runs a relay and a sensor process. The relay writes a persistent volume; the sensor reads the token file through a read-only mount. A reverse proxy provides TLS. Compose enables demo users by default; the server alone does not.
